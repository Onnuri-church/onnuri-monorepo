# 온누리 온 (부산온누리교회 온)

부산온누리교회 성도와 방문자를 위한 iOS/Android 앱입니다. 설교 영상, 주보, 큐티 나눔, 기도 제목, 부서 활동, 셀 출석, 채팅을 **외부 링크로 나가지 않고 앱 하나에서** 이용할 수 있습니다. 청년부 공동체(약 100명)부터 사용을 시작해 교회 전체로 넓혀 가고 있습니다.

| 서비스 링크 | (출시 후 App Store 주소 추가) |

## 왜 만들었나

교회 행정(출석, 셀 편성, 주보 배포, 공지)이 수기와 메신저 단체방에 흩어져 있었습니다. 담당자는 매주 같은 일을 손으로 반복했고, 성도는 설교 영상·주보·공지를 서로 다른 곳에서 찾아야 했습니다. 이 일을 직접 맡아 하던 중 앱으로 옮기면 양쪽 부담이 줄겠다고 판단해 담임 교역자에게 제안했고, 프로젝트의 기획과 완성을 맡아 시작했습니다.

## 주요 기능

- **홈**: 이번 주 설교, 주보, 기도 제목, 부서 활동을 한 화면에 모아 보기
- **말씀**: 교회 유튜브 채널을 5분마다 읽어 설교 영상을 자동 등록, 앱 안에서 재생
- **주보·나눔지**: 주차별 이미지 열람(확대), 관리자 업로드
- **게시판**: 큐티 나눔, 기도 제목(익명), 부서 활동, 팀 게시판 — 댓글·반응·신고·차단
- **셀·출석**: 셀 편성, QR 출석, 셀장 출석 기록, 활동 종료일 자동 처리
- **채팅**: 리더방·단체방, 사진 묶음 전송, 공지, 투표, 답장, 검색
- **취향 소그룹**: 모임 개설, 가입 신청·승인
- **관리자**: 회원 관리, 권한 지정, 자료 내려받기
- **계정**: 카카오·구글·Apple 로그인, 로그인 없이 둘러보기, 회원 탈퇴(30일 후 개인정보 삭제)
- **기타**: 푸시 알림(눌러서 해당 화면 이동), 다크 모드, 한국어·영어

## 구조

```
모바일 앱 (Expo / React Native)
        │  HTTPS, JWT (액세스 + 리프레시 회전)
        ▼
API 서버 (NestJS, Render)
        │  Prisma
        ▼
PostgreSQL + 파일 저장소 (Supabase)

외부 연동: 카카오·구글·Apple 로그인, YouTube Data API, Expo Push, Sentry
```

```
onnuri-monorepo/
├── apps/
│   ├── mobile/      React Native (Expo) 앱
│   └── api/         NestJS 서버 (modules/ 도메인별, prisma/ 스키마·마이그레이션, test/ E2E)
├── packages/
│   ├── shared/      앱·서버가 함께 쓰는 타입·상수·약관 문구
│   └── config/      공유 ESLint·tsconfig
├── docs/            ERD, 설계 문서, 작업 계획
└── scripts/         커밋 규칙 검사 등
```

자세한 구조와 결정 기록은 [ARCHITECTURE.md](ARCHITECTURE.md), 화면 규칙은 [apps/mobile/DESIGN.md](apps/mobile/DESIGN.md)에 있습니다.

## 기술 선택과 이유

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 앱 | Expo (React Native) | 적은 인원으로 iOS·Android를 함께 만들 수 있고, 스토어 심사 없이 수정본을 배포(OTA)할 수 있음 |
| 서버 | NestJS | 모듈·가드·DTO 구조가 정해져 있어 여러 사람이 같은 모양으로 코드를 씀 |
| 서버 구조 | Controller + Service 2계층 | 지금 규모에서 Repository·Domain 계층은 없는 문제를 미리 대비하는 비용이라 판단 |
| DB | PostgreSQL + Prisma | 출석·멤버십처럼 관계가 많은 데이터, 스키마 변경 이력을 마이그레이션으로 관리 |
| 저장소 구성 | pnpm 모노레포 | 앱·서버가 타입과 약관 문구를 공유, API 변경을 한 PR에서 함께 검토 |
| 서버 호스팅 | Render | 저장소 연결만으로 배포. Vercel은 서버리스라 상시 실행 서버에 맞지 않고, AWS는 운영 부담이 큼 |
| DB·파일 | Supabase | DB와 파일 저장소를 한 곳에서 관리, 비공개 파일용 서명 URL 기본 제공 |
| 서버 상태 | TanStack Query | 캐시와 재요청 규칙을 화면마다 다시 만들지 않기 위해 |
| 오류 추적 | Sentry | 개인정보 전송은 끄고(`sendDefaultPii: false`) 오류만 수집 |

## 운영

- **브랜치**: `dev`(작업, 개발 서버 자동 배포) → `main`(운영 서버 자동 배포). 스키마 변경은 추가만 하는 형태로 써서 구버전 앱이 깨지지 않게 합니다.
- **작업 단위**: Jira 티켓 → 브랜치 → PR → 리뷰 → 머지. 커밋 제목 형식은 훅이 검사하고, PR 본문은 Jira에 자동 기록됩니다. ([CONTRIBUTING.md](CONTRIBUTING.md))
- **지표**: 일별 활성 사용자와 요청별 응답 시간·오류를 서버가 직접 기록해, 느린 API와 사용 흐름을 숫자로 확인합니다.
- **피드백**: 성도 테스터와 현직 개발자의 제보를 티켓으로 쌓고 우선순위를 정해 반영합니다.
- **심사 대응**: 심사 중에는 운영 서버 배포를 멈추고, 수정은 `dev`에만 모읍니다.

## 실행 방법

```bash
pnpm install
cp apps/api/.env.example apps/api/.env        # 값 채우기
cp apps/mobile/.env.example apps/mobile/.env
pnpm --filter @onnuri/api exec prisma migrate deploy
pnpm --filter @onnuri/api run start:dev
pnpm --filter @onnuri/mobile exec expo start
```

패키지 매니저는 pnpm만 씁니다. 소셜 로그인과 푸시는 개발 빌드가 필요합니다.
