# 출석·회원 데이터 설계

> **상태: 초안 (검토 필요)** — 확정 전 팀 검토 필요. 2026-09-01 확정 사항 반영(부셀장·게스트·승격 구조·팀 멤버십 등), 구조 확정본은 [erd.md](erd.md).
> **백엔드 개발(모듈/Prisma 스키마/`packages/shared` 타입)에 착수하기 전에 이 문서를 먼저 확인한다.**
> 담당: 마이페이지·설정·셀 (회원/출석 데이터)

## 0. 목적

청년부 앱의 **회원 정보 + 출석 데이터**를 어떻게 저장하고, 관리자가 어떻게 **엑셀로 추출**하는지 정의한다. 백엔드 데이터 모델(Prisma) 및 공유 타입(`packages/shared`) 설계의 근거 문서다.

> 참고: 출석/QR/어드민/엑셀 추출은 [README](../README.md) 기준 **"추가 기능"(MVP 이후)** 이다. 이 문서는 그 기능들의 데이터 구조를 미리 잡아두기 위한 설계이며, 지금 당장 구현 대상은 아니다.

## 1. 등급 (권한)

| 등급 | 할 수 있는 것 |
|---|---|
| **일반 유저** | 본인 출석(QR), 본인 프로필 조회/수정 |
| **팀장** | 일반 + 자기 팀 페이지 관리: 팀 소개글 작성, 활동 사진 추가(팀 갤러리), 팀원 추가, 자기 팀 게시판 작성 |
| **셀장 (팔로워)** | 일반 + **본인 셀의 셀모임 출석** 수정 (다른 셀 불가), 셀 페이지 수정. **부셀장은 셀장과 동일 권한** (셀장+부셀장 합쳐 최대 2명) |
| **관리자(임원)** | 전체 회원·출석 조회, **엑셀 추출**(전용 마이페이지에서 검색·다운로드), **모든 게시물 접근·삭제**, **익명 기도제목 작성자 확인**, **유저 승강격**, **셀/팀 페이지 생성·수정·삭제**, 잘못 인입된 설교 영상 삭제 |

- `게스트`(비로그인): 팔로워 노트·출석 관리·셀원 관리를 **빼고 전부 열람 가능**. 작성·신청 등 활동을 시도하면 "로그인해야 가능합니다" 다이얼로그로 로그인 유도. DB에 행을 만들지 않는다.
- `관리자`: 유저에 플래그로 지정 (회원가입 X, 임원을 수동 지정).
- `셀장`: 별도 플래그가 아니라 **셀 멤버십의 역할 = 셀장** 인 사람 (아래 3.3 참고). "팔로워"라고도 부른다.
- `팀장`: **팀 멤버십의 역할 = 팀장** (2026-09-01 확정 — 셀 멤버십과 같은 구조, [erd.md](erd.md) 참고). 자기 소속 팀에 대해서만 권한을 가진다.
- **승격 구조**: 팀장·셀장은 관리자가 일반 유저를 승격/강등시키는 것 (= 멤버십 역할 변경). 승격자는 해당 페이지 **수정만** 가능하고, 생성·삭제는 관리자 전용.
- 팀장과 셀장은 서로 독립이다 — 한 사람이 둘 다일 수 있다 (팀 소속과 셀 소속이 별개이므로).
- 현재 아키텍처는 단일 등급(Guest/User)만 존재 — 등급 확장은 [ARCHITECTURE.md](../ARCHITECTURE.md) "Access Model"의 향후 스코프.
- 팀 목록(7팀): 찬양팀, 디자인팀, 방송팀, 영상팀, 중보기도팀, 풋살팀, SNS팀.

## 2. 출석 시스템 규칙

**흐름** (2026-09-03 확정: QR은 예배 출석만 기록한다)
1. 예배 전 **QR 안 찍음**(마감 시각까지) → 예배 ❌ · 셀모임 ❌ (둘 다 결석)
2. 예배 와서 **QR 찍음** → 예배 ✅ · 셀모임 ❌ (셀모임은 아직 결석)
3. 셀모임 시작 → **셀장**이 "출석관리" 화면에서 온 사람만 체크 → 셀모임 ✅ — 그 주 예배 QR 명단을 참고로 표시해주면 확인이 빠르다

**표기 (예배/셀모임)**

| 상황 | 표기 |
|---|---|
| 예배만 참석 | `O/X` |
| 셀모임만 참석 | `X/O` |
| 둘 다 참석 | `O/O` |
| 둘 다 결석 | `X/X` |

> 온라인 예배는 **출석으로 인정하지 않음** (설계에서 제외).

## 3. 데이터 구조 (저장)

낱개 원본만 저장하고, 통계는 뽑을 때 계산한다(§5).

### 3.1 유저 (잘 안 바뀜)

| 개념 | 예시 | 출처 |
|---|---|---|
| 유저ID | U001 | 자동 |
| 이름 | 홍길동 | 소셜 로그인 |
| 이메일 | — | 소셜 로그인 |
| 생년월일 | 2000-03-10 | 프로필 (화면 확정: 전체 생년월일 수집 — §6 개인정보 동의. 나이는 계산) |
| 성별 | 남 | 프로필 |
| 소속 팀 | 찬양팀 | **팀 멤버십**(역할·기간)으로 관리 — 2026-09-01 확정, §3.3의 셀 멤버십과 같은 구조 ([erd.md](erd.md)) |
| 관리자 여부 | false | 임원만 지정 |

### 3.2 셀 (생성·종료 있음)

셀은 이름으로 구분하고, 존재 기간(유통기한)이 있다. **생성은 관리자 전용** — 셀 이름·셀장(부셀장 포함 최대 2명)·셀원·유통기한·단체 사진(402×402 커버) 5가지를 지정하면 소식/갤러리/구성원/관리 4탭 셀 페이지가 자동 생성된다.

| 개념 | 예시 |
|---|---|
| 셀ID | C01 |
| 셀이름 | 누리셀 |
| 단체 사진 | 셀 페이지 상단 커버 (402×402) |
| 생성일 | 2025-03-01 |
| 유통기한 | 2025-08-31 (활동 종료 예정일) |

- 유통기한이 **자연 만료되면 삭제가 아니라 "종료" 처리**로 출석 기록을 보존한다.
- 운영 중엔 관리자가 언제든 강제 수정(셀원·셀장·기한·사진) 및 **삭제** 가능 — 삭제해도 출석 기록은 보존한다 (2026-09-04 확정, §6).

### 3.3 셀 멤버십 (누가·어느 셀·역할·기간)

**셀은 3·6·12개월 등 불규칙하게 바뀌므로, "연도"가 아니라 "기간(시작~종료일)"으로 관리한다.**

| 유저ID | 셀ID | 역할 | 시작일 | 종료일 |
|---|---|---|---|---|
| U001 | C01 (지환셀) | 셀원 | 2025-03-01 | 2025-08-31 |
| U001 | C05 (지현셀) | 셀장 | 2025-09-01 | 2026-02-28 |

- `역할`: 셀장 / **부셀장** / 셀원 — 같은 사람이 셀마다 다를 수 있음. 부셀장은 셀장과 동일 권한 (2026-08-24 확정).

### 3.4 출석 (예배 하루당 한 줄)

| 유저ID | 예배날짜 | 예배참석 | 셀모임참석 |
|---|---|---|---|
| U001 | 2025-03-09 | O | X |

- `예배참석`: QR로 기록 (기본 X).
- `셀모임참석`: 셀장이 기록 (기본 X).

### 관계도

```
유저 ─┬─(유저ID)─ 셀 멤버십 ─(셀ID)─ 셀
      └─(유저ID)─ 출석
```

각 표는 **유저ID / 셀ID로 연결**한다 (이름 대신 ID로 매칭 → 동명이인 대비).

## 4. 엑셀 추출 (관리자 전용)

### 4.1 대상·기간 필터

- **대상**: 전체 / 셀별(셀 선택) / 개인(이름 검색 후 1명 또는 여러 명)
- **기간**: 전체 / 올해 / 작년 / 직접 선택(시작~종료)

### 4.2 시트 1 — 유저 정보

| 유저ID | 이름 | 생년월일(나이) | 성별 | 소속 팀 |
|---|---|---|---|---|
| U001 | 홍길동 | 2000-03-10 (26) | 남 | 찬양팀 |

### 4.3 시트 2 — 출석부 (셀 기간별, 한 사람이 여러 줄)

| 유저ID | 이름 | 셀 | 역할 | 기간 | 3/2 | 3/9 | … | 예배만 | 셀모임만 | 둘다 |
|---|---|---|---|---|---|---|---|---|---|---|
| U001 | 홍길동 | 지환셀 | 셀원 | 25.03~25.08 | O/O | O/X | … | 5 | 1 | 18 |
| U001 | 홍길동 | 지현셀 | 셀장 | 25.09~26.02 | O/O | X/O | … | 3 | 2 | 20 |

- 각 날짜 칸 = `예배/셀모임`.
- 끝 3칸 = 해당 셀 기간의 **예배만 / 셀모임만 / 둘다** 참석 총횟수.
- 출석률은 이번 설계에서 제외.

## 5. 저장 원칙 (계산 vs 저장)

| 항목 | 저장? |
|---|---|
| 이름·성별·생년월일·팀·셀·출석 O/X | ✅ 저장 (원본) |
| 나이 | ❌ 생년월일로 **계산** |
| 참석 횟수(예배만/셀모임만/둘다) | ❌ O/X로 **계산** |

> 통계를 저장하지 않는 이유: 출석 기록을 나중에 수정하면 저장된 숫자가 어긋난다. 원본만 저장하고 뽑을 때 계산하면 항상 정확하다.

## 7. 향후 스코프 / 참고

- QR 출석·어드민 권한·엑셀 추출은 **MVP 이후** 기능. 지금은 데이터 구조만 확정한다.
- 등급 확장 시 [ARCHITECTURE.md](../ARCHITECTURE.md) "Access Model"의 capability 기반 가드 방식으로 구현하고, 리소스 소유권 검증(셀장은 본인 셀만)을 반드시 추가한다.
